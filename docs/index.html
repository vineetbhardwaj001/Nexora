The idea

Good workflows should travel with you.

Not everyone codes in the same environment. Nexora is being shaped around a shared source of useful instructions, with tool-specific setup kept separate.

🧭

Start with clarity

Turn an early idea into a clear goal, realistic scope, acceptance criteria, and the next sensible step.

🎨

Design with intention

Study UI references, explain design decisions, and build interfaces that feel coherent and accessible.

🔌

Respect the backend

Understand existing routes and data contracts before wiring up a frontend. No made-up endpoints.

🧱

Keep code maintainable

Prefer clear boundaries, product-domain folders, small components, and predictable conventions.

🧪

Test what matters

Make room for validation, regression checks, accessibility, and security review as the project grows.

🤝

You stay in control

Understand what is about to change. Preserve existing work and confirm risky or destructive actions.

Before using Nexora in a different project: make a backup of its existing agent instructions and review the changes before merging them. The CLI's current behavior and any limitations should be verified locally; don't assume it configures every tool automatically.

Choose your environment

Your tool. Your workflow.

The shared-skill idea is portable, but agent formats and delegation features differ. Nexora should adapt to each tool instead of pretending every tool works the same way.

Compatibility is more than a file copy. A SKILL.md may provide reusable instructions, but it does not automatically become a native subagent. The final installer should validate supported formats, back up conflicts, offer dry-run mode, and explain any unsupported features.

Keep costs visible

Free-model-only is a policy, not a promise.

The plan is to help users avoid accidental paid fallbacks. It needs provider-aware configuration and testing; a sentence in an agent prompt cannot guarantee zero cost.

⚡

Planned: strict free-only mode

A future model policy would allow only model IDs verified as free at setup time, explain limits, and stop when no eligible endpoint is available. Users would manage their own provider credentials.

1. Verify firstCheck current provider pricing, quotas, and the user's own plan.
2. Allowlist onlyOnly explicitly eligible zero-cost models can be selected for free-only mode.
3. Fail closedIf no eligible model is available, stop and explain. Never silently switch to paid.
!

Current status: this is a roadmap item, not an implemented billing safeguard. Free tiers can change, and user-owned API keys (BYOK) do not automatically mean requests are free. Verify provider settings before sending important code or confidential data.

Trust is a feature

The goal is not to let an agent do everything without asking. It is to make the next safe action easy to understand.

Good questions

Before you dive in.

A few plain answers to common questions.

Is Nexora already a universal multi-agent runtime?

No. It is an early-stage CLI and instruction/skill starter. The universal adapter and pack-management experience is planned and needs implementation and real compatibility testing.

Can I use it with Kilo Code, OpenCode, or Antigravity?

The project is designed to explore those integrations, but support must be tested for each tool and version. Shared Markdown instructions do not guarantee native agent delegation in every environment.

Do I need npm right now?

No. For the current workflow, clone the GitHub repository and test locally. Publishing to npm is paused while the project is being tested and improved.

Will free-only mode guarantee that no money is charged?

Not yet. It is a planned feature. It must use provider-aware allowlists and safe failure behavior, and users should verify pricing and billing settings themselves.

Can I help improve Nexora?

Yes. Start with CONTRIBUTING.md, check the existing issue tracker, and submit focused changes with clear tests or reproduction steps.

Have an idea for a better workflow?

Nexora is being built iteratively. A clear issue or small reproducible example is a great way to help shape what comes next.
