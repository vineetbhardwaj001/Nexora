# Contributing to Nexora

Thanks for helping improve Nexora.

## Before opening an issue
- Search existing issues and discussions.
- Include the IDE/tool and version, operating system, expected behavior, actual behavior, and reproducible steps.
- Redact access tokens, API keys, private repository details, and user data.

## Pull requests
1. Keep changes focused and explain the user problem being solved.
2. Update relevant skill instructions, workflows, and README documentation.
3. Do not change backend-protection rules without explaining the safety implications.
4. Do not add third-party code until its license and dependencies have been reviewed.
5. Run the available checks locally and include the commands/results in the PR.
6. Never claim compatibility with an IDE/version unless tested.

## Skill contribution checklist
- [ ] Clear name, description, and activation criteria
- [ ] Concrete workflow and expected outputs
- [ ] Safety and approval boundaries
- [ ] No secrets or proprietary assets
- [ ] Documentation updated
- [ ] Relevant automated checks pass
