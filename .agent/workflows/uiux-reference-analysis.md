# UI/UX Reference Analysis Workflow

## Goal
Analyze each user-supplied image separately, then synthesize a product-specific direction. Do not average all images into one style or assume they belong to one brand.

## For every image, record
- Reference ID/filename and apparent screen/page type
- Palette roles: background, surface, text, accent, border, muted and status colors; mark hex values estimated unless sampled
- Typography roles: display, body, labels, monospace; weight, scale, line-height and readability
- Layout: grid, columns, max width, alignment, whitespace and hierarchy
- Components: navigation, forms, buttons, cards, tabs, chips, lists, sidebars and bottom navigation
- Image/illustration/texture treatment, borders, shadows and depth
- Interaction/motion clues; static images only support hypotheses
- Responsive risks, accessibility, contrast and touch targets
- Reusable principles vs brand-specific assets/copy
- Confidence: observed, inferred, unknown

## Workflow
1. Understand product, audience, main task, trust needs, conversion goal, constraints and stack.
2. Analyze all references individually before comparison.
3. Cluster style families (e.g. editorial, playful, illustrated, premium, dashboard, mobile content app).
4. Select one coherent direction based on product fit, usability, accessibility, and maintainability.
5. Propose tokens: colors, typography, spacing, radii, borders, shadows, grid and breakpoints.
6. Define page hierarchy, components, states, responsive behavior and accessibility.
7. Ask for approval before major changes unless implementation was explicitly requested.
8. Verify desktop/tablet/mobile, keyboard/focus, contrast, reduced motion, loading/empty/error/success states and asset performance.

Never copy logos, artwork or proprietary copy blindly. Do not claim exact font names, sampled colors or animation behavior without verification.
